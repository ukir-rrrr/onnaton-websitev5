## 0. 絶対遵守（作業前に必読）

### 0-1. Git：ブランチ必須・main 禁止

**必ずブランチを切って作業すること。`main` には絶対に混ぜない。**

1. 作業開始直後に、**前回作業ブランチの先端**から新規ブランチを切る。  
   ベース: `v5/cursor/owner-revisions-20260907-e1f7`  
   （これが `v5/main` にマージ済みなら `v5/main` から切る。切る前に `git log` でコース刷新コミットがあるか確認すること。）  
   例: `owner-revisions-20260908`
2. **以後のすべての commit はそのブランチだけに置く。**
3. **`main` への merge / rebase / cherry-pick / push は禁止。**
4. commit と **作業ブランチの push** はしてよい。
5. PR を作る場合も **マージしない**（Draft PR まで可）。
6. このマシンの本番 GitHub はリモート **`v5`**（`https://github.com/ukir-rrrr/onnaton-websitev5.git`）。  
   `origin` は古い v4（`onnaton-websitev4`）のことがある。  
   **push 先は `v5`。`origin`（v4）へは push しない。**  
   `git push -u v5 HEAD`
7. 作業完了報告には **ブランチ名** と **push したリモート / SHA** を書く。`main` の SHA を報告しない。

### 0-2. サブエージェントによるレビュー必須

実装が終わったら、**別のサブエージェント**（親エージェント自身の自己申告では不可）にレビューさせる。

- この指示書の **①〜⑥の全完了条件** を渡す。
- レビュー担当はコードを読み、各項目を **PASS / FAIL** で返す。推測で PASS にしない。
- FAIL があれば直して **再レビュー**。全部 PASS になるまで完了としない。
- レビュー結果の要約を最終報告に含める。

### 0-3. リポジトリの性質

- Next.js **16.3.3** / React 19 / Tailwind CSS v4 / TypeScript。App Router。
- ルート直下 `AGENTS.md` に従い、必要なら `node_modules/next/dist/docs/` を読んでから書く。
- デプロイ先は Cloudflare Workers。今回は **デプロイしない**（ブランチ push まで）。
- **既存デザインを維持し、変更箇所だけ直す。**
- 変更のない文章・注意書き・他言語は触らない。
- フォント切り替え（`lib/content/courseMenuFont.ts`）は今回の対象外。触らない。
- UI 変更後はスマホ・PC の該当画面を確認する。ブラウザが無ければクラスと改行データを根拠として残す。
- `npm run lint` を通す。秘密情報はコミットしない。

### 0-4. i18n（ここを間違えると他言語が壊れる）

ロケールは **ja / en / yue / zhTw / ko**。

**(A) `lib/i18n/copy.ts`**


**(B) `lib/content/*.ts` の日本語は `lib/i18n/phrases.ts` で翻訳**

- 日本語原文がキー。キー文字列を変えたら `phrases.ts` + `yue-phrases.ts` + `zhTw-phrases.ts`（または translations.json 再生成）も更新する。

## ② セット内容の「※」カラー統一

### 対象
- `components/course/ExecutiveCourse.tsx`
- 補足文は `copy.coursePage.setNote`（**文面は変えない**）

### 現状
- 各セット対象料理の上の「※」は `text-gold`。
- 補足文は全文が `text-cream/80`。現行 JA 文面は  
  `※印のついた内容がセット内容です。`

依頼文中の「※印の付いた商品はセットに含まれています。」は説明用。**文言は現行のまま**にする。

### やること

補足文を「先頭の ※」と「それ以降」に分けて描画する。

- 先頭の `※` → 料理上の ※ と **同じ `text-gold`**
- 残りの文字 → いまどおり通常色（`text-cream/80` など）

**横書き（スマホ／海外）と縦書き（JA PC）の両方**で同じ処理をする。  
シャトーブリアン（セットなし）には補足文自体が出ない。そのままでよい。

海外の setNote も先頭が `※` なら同様。`Items marked with ※` のように途中に ※ があるだけの英文は、**先頭が ※ のときだけ**金色にする（無理に英文の途中の ※ を金色にしなくてよい）。

### 完了条件
- 料理上の ※ と、補足文先頭の ※ が同じゴールド。
- 補足文の本文色は変わっていない。
- setNote の文言（5言語）は変更していない。

## ③ 日本語・PC版のみ コースメニューの余白調整

### 対象
- `components/course/ExecutiveCourse.tsx` の **縦書きブロックだけ**  
  （`isJa` かつ `xl:block` の tategaki。現行はおおよそ 265行付近）

### 触ってはいけないもの
- スマホ／タブレットの横書き（yokogaki）
- 海外4言語ページ（縦書きを出さない）
- コース名・料理名・価格・※の意味

### 現状（目安）
縦書き行はだいたい次の gap。

`gap-2` / `min-[1440px]:gap-3` / `min-[1600px]:gap-5` / `min-[1800px]:gap-7`

右端クリップ対策で `xl:max-w-none` と小さめ gap になっている。余白を広げすぎて **右のコース名やゴールド帯が再び切れない**こと。切れそうなら gap より先に、列間だけ段階的に広げる。

### やること（3点とも「少し」）

1. **コース名〜金額のエリアを、いまより少し右へ離す**  
   画面右端（またはゴールド帯）とのあいだに、わずかな余白を足す。  
   例: 縦書きコンテナの右側 padding を少し増やす。
2. **金額列と、いちばん右の料理列のあいだ**を、他の列間より少し広くする。  
   全体 gap を一律で大きくしすぎない。金額の左（見た目では料理側）にだけ余白を足すのが安全。
3. **料理の縦書き列同士**の間隔を、いまより少し広げる。

「今より全体的に少しゆとり」が目的。倍増はしない。デザインの和風・縦書きは維持。

### 完了条件
- JA の xl 以上だけで余白が広がっている。
- スマホ・海外のコースページの間隔は変わっていない。
- 極／煌の右端（コース名・ゴールド帯）が切れていない。
