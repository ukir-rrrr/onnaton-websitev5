## 0. 絶対遵守（作業前に必読）

### 0-1. Git：ブランチ必須・main 禁止

**必ずブランチを切って作業すること。`main` には絶対に混ぜない。**

1. 作業開始直後に、最新の `main` から新規ブランチを切る。  
   例: `owner-revisions-20260907`
2. **以後のすべての commit はそのブランチだけに置く。**
3. **`main` への merge / rebase / cherry-pick / push は禁止。**
4. commit と **作業ブランチの push** はしてよい。
5. PR を作る場合も **マージしない**（Draft PR まで可）。
6. このマシンの本番 GitHub はリモート **`v5`**（`https://github.com/ukir-rrrr/onnaton-websitev5.git`）。  
   `origin` は古い v4（`onnaton-websitev4`）のことがある。  
   **push 先は `v5`。`origin`（v4）へは push しない。**  
   `git push -u v5 HEAD`
7. 作業完了報告には **ブランチ名** と **push したリモート / SHA** を書く。`main` の SHA を報告しない。

### 0-2. サブエージェントによるレビュー必須

実装が終わったら、**別のサブエージェント**（親エージェント自身の自己申告では不可）にレビューさせる。

- レビュー専用プロンプトでこの指示書の **①〜⑧＋ソフトドリンクの全完了条件** を渡す。
- レビュー担当はコードを読み、各項目を **PASS / FAIL** で返す。推測で PASS にしない。
- FAIL があれば実装エージェントが直して、**再レビュー**する。全部 PASS になるまで完了としない。
- レビュー結果の要約を最終報告に含める。

推奨: `Task` で `subagent_type="generalPurpose"` または `explore`（thoroughness: very thorough）。  
プロンプト例: 「`docs/2026-09-07-owner-revisions.md` の完了条件を全部チェックし、項目番号ごとに PASS/FAIL と根拠ファイルを返せ。main に混ざっていないかも確認。」

### ⑧-③ セット内容の ※ と補足

料理一覧の全品がコース内容。セットに含まれるものだけ ※ で示す。

補足文（S・華・極・煌のみ。シャトーブリアンには出さない）:

```
※印のついた内容がセット内容です。
```

他言語は同じ意味を、既存トーンで:

- EN: 例 `Items marked with ※ are included in the set.`
- KO / yue / zhTw: それに相当する1文。phrases に追加。

**補足文の位置（日本語縦書き）:**  
料理一覧の **一番左**（`flex-row-reverse` なので **最後の child**）に、少し余白を空けて縦書き。シャトーブリアン注意書きと同じスロット発想。

**※ の付け方（日本語縦書き・厳守）:**

- 料理名文字列の先頭に `※` を埋め込まない。
- ※ は料理名とは **別要素**で、その料理カラムの **上**に置く。
- ※ あり／なしで料理名の開始位置がずれない。  
  → 全料理に同じ高さの「※スロット」を確保し、非セットは空にする、など。
- 料理名の縦書きスタート位置は、今と同じ横ラインで揃える。

横書き（スマホ・海外）: 名前の左に幅固定の ※ 列を置き、名前の開始位置を揃えてよい。名前文字列自体に ※ を連結しないのが望ましい。
